# RPC Implementation Mechanism in Distributed System - GeeksforGeeks

RPC implementation refers to the internal mechanism that enables a client to invoke a procedure on a remote server as if it were a local function call.Provides the technical framework for remote communicationManages interaction between client and server componentsHandles data conversion and message transmissionRole of Client and Server StubsThese act as intermediaries that manage communication and data conversion between distributed components.Client and Server StubClient stub converts procedure arguments into message format.Server stub converts received messages back into procedure parameters.Client remains blocked in synchronous RPC until a response is received.In asynchronous RPC, the client continues execution without waiting.Stubs hide network communication details from the application.Working MechanismThe working mechanism of RPC describes the step-by-step process through which a remote procedure call is executed between a client and a server in a distributed system. Procedure Call Initiation: The client invokes the remote function as if it were a local call.Marshalling: The client stub converts parameters into a structured message format suitable for network transmission.Message Transmission: The RPC runtime sends the request message from the client machine to the server machine.Unmarshalling: The server stub converts the received message back into the original parameters.Execution and Response: The server executes the procedure and sends the result back to the client through the same process in reverse order.RPC ProcessThis explains how a remote procedure call is executed through coordinated communication between client and server components.Client, client stub, and one instance of RPC runtime execute on the client machine.Client invokes a procedure like a normal local call with parameters.Client stub allocates memory in the client address space and marshals parameters into a request message.RPC runtime transmits the request message over the network to the server machine.Server stub receives the message and unmarshals the parameters.The server executes the requested procedure.Server stub marshals the return values into a response message.The transport layer sends the response back to the client machine.Client stub unmarshals the returned values and passes the result to the caller.Parameter Passing in RPCThis defines how arguments are transferred from the client to the remote server procedure during execution.1. Call by ValueA copy of the actual parameter is sent to the remote serverChanges made on the server do not affect the original variableMost commonly used method in RPC systemsSuitable for distributed environmentsEnsures safer and predictable execution2. Call by Reference (Limitations in Distributed Systems)Memory addresses cannot be directly shared across machinesTrue call-by-reference is not feasible in distributed systemsInstead, a copy–restore mechanism may be usedIncreases communication overheadMay cause inconsistency if network failure occurs during executionTypes of RPCRPC can be classified based on how the client handles the execution and response of a remote procedure call.1. Synchronous RPCThis is a type of remote procedure call in which the client waits for the server to complete execution and return the result before continuing. Follows a blocking communication modelClient execution pauses until a response is receivedSimple and predictable execution flowEasier error handling mechanismSuitable for request–response applications2. Asynchronous RPCThis is a type of remote procedure call in which the client does not wait for the server's response and continues execution after sending the request.Follows a non-blocking communication modelClient performs other tasks while waiting for a responseImproves system responsivenessSuitable for high-latency networksIncreases complexity in result handling
