# Distributed File System and Shared Memory - GeeksforGeeks

A Distributed File System (DFS) lets multiple clients access and share files stored across different physical machines as if they were on a local disk, while Distributed Shared Memory (DSM) extends that illusion of a single shared address space across networked machines.Presents files spread across multiple servers under a single, location-transparent namespace.Handles replication and caching to improve performance and availability.Uses fault-tolerance mechanisms like atomic commit protocols to keep data consistent despite failures.DSM lets processes on separate machines share data through a common memory abstraction instead of explicit message passing.Consistency models define how up-to-date a read is guaranteed to be after a write elsewhere in the system.Distributed File System ArchitectureDFS BasicsCharacteristics of File systemNetwork file system architectureAndrew file systemDesign Principles of DFSFile Service Architecture and ModelsThe components that define how a DFS presents, locates, and manages files for clients. They can be broadly categorized into:File Service ArchitectureFile Service ArchitectureFile Service Architecture describes how the directory service, flat file service, and client module together provide file access over a network.File ModelsFile Models define how a file is structured and interpreted as an unstructured byte stream, a record sequence, or a tree.File-Accessing ModelsFile-Accessing Models describe how clients read and write remote files:Remote service model: requests are sent to the server for every access.Data-caching model: file data is cached locally to reduce network traffic.File-Sharing SemanticsFile-Sharing Semantics define what guarantees a client gets when multiple processes access the same file concurrently — Unix semantics, session semantics, and transaction semantics.File-Caching SchemesFile-Caching Schemes determine where cached file data lives (client memory, client disk, or server) and how cache consistency is maintained.Replication and Fault ToleranceReplication: Storing multiple copies of a file across servers to improve availability and fault tolerance.Atomic commit protocol: Ensures a distributed transaction either commits on all participating servers or none at all.Distributed Shared Memory (DSM)Distributed shared memory provides processes on different machines a shared logical address space, avoiding explicit message-passing code and simplifying parallel programming.Architecture of Distributed shared memory: How DSM is layered over the underlying network and memory management units.Uniform Memory Access (UMA) vs Non-uniform Memory Access (NUMA): UMA gives every processor equal-latency access to all memory; NUMA gives faster access to local memory over remote memory.Design and implementation issue of distributed shared memory: Covers granularity, replacement strategy, and thrashing control.Algorithm for implementing DSM: Includes central-server, migration, read-replication, and full-replication algorithms.Consistency and PerformanceConsistency models: Define the rules (strict, sequential, causal, weak, etc.) governing when writes become visible to other processes.Thrashing in Distributed shared memory: Occurs when data is moved between nodes repeatedly, degrading performance instead of improving it.
