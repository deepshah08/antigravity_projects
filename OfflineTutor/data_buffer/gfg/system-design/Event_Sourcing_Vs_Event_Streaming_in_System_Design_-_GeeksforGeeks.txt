# Event Sourcing Vs Event Streaming in System Design - GeeksforGeeks

Event Sourcing and Event Streaming are related concepts used in modern system design, but they solve different problems. Event Sourcing focuses on storing application state changes as an authoritative history of events, while Event Streaming focuses on continuously publishing, transporting, and processing events between systems.Event Sourcing: Stores state changes as events so application state can be reconstructed from the event history.Event Streaming: Continuously delivers and processes streams of events for analytics, integration, monitoring, and event-driven workflows.Event SourcingEvent Sourcing is a data persistence pattern that stores application state changes as a sequence of immutable events rather than storing only the latest state. These events provide a complete history of changes and allow the current state to be reconstructed.Event Storage: Records state changes as events such as AccountOpened, MoneyDeposited, and MoneyWithdrawn.State Reconstruction: Replays stored events in sequence to rebuild the current or previous application state, optionally using snapshots to improve performance.Example: In a banking system, instead of storing only the final account balance, every transaction like “Money Deposited”, “Money Withdrawn”, and “Transfer Completed” is stored as an event. The current balance is calculated by replaying all these events in order.Event StreamingEvent Streaming is a data processing approach where events are continuously published to a stream and consumed by applications as they become available. It enables near-real-time data processing and communication between systems.Continuous Event Processing: Producers publish events to a stream, allowing multiple consumers to process them independently and at different speeds.Common Use Cases: Used in data pipelines, real-time analytics, monitoring, log processing, IoT applications, financial feeds, and event-driven integration.Example: In a ride-sharing application like Uber, every activity, such as “Ride Requested”, “Driver Assigned”, “Driver Arrived”, and “Ride Completed”, is continuously published as an event to a streaming platform.
