# How are Java Objects Stored in Memory? - GeeksforGeeks

In Java, memory is managed automatically by the Java Virtual Machine (JVM). When a program creates an object, the JVM allocates memory for it and manages that memory throughout the object's lifecycle.Java objects are generally allocated in heap memory.Local variables and local object references are associated with a method's stack frame.The new keyword is commonly used to create an object and obtain a reference to it.Memory AreasThe JVM uses different runtime memory areas for executing Java programs. For understanding object storage, the most relevant areas are:Metaspace: Stores class metadata and uses native memory.1. Heap MemoryHeap memory is the runtime memory area from which memory for Java objects and arrays is generally allocated. Objects created using the new keyword are typically stored in the heap.For example:Scanner sc = new Scanner(System.in);new Scanner(System.in) creates a Scanner object that is generally allocated in heap memory.sc is a local reference variable associated with the current method's stack frame and refers to the Scanner object.Note: Heap memory is managed automatically by the JVM, and memory occupied by unreachable objects can be reclaimed through garbage collection.Heap GenerationsFor generational garbage collectors, the heap can conceptually contain regions for objects of different ages:Young Generation: Generally contains newly allocated objects.Old Generation: Generally contains objects that have survived multiple garbage collection cycles and remain reachable for a longer period.Class metadata should not be described as objects stored in the Old Generation. In modern Java, class metadata is maintained separately in Metaspace.Permanent Generation and MetaspaceIn Java 7 and earlier HotSpot JVMs, Permanent Generation (PermGen) was used for class-related metadata. Starting with Java 8, PermGen was removed and replaced by Metaspace, which uses native memory rather than the Java heap.Example
            Java

    class Student {
    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

public class Geeks {
    public static void main(String[] args) {
        Student s = new Student("Bob", 20);
    }
}

OutputExplanation:new Student("Bob", 20) creates a Student object that is generally allocated in heap memory.s is a local reference variable associated with the main() method's stack frame and refers to that object.The instance fields name and age are part of the Student object's state.2. Stack MemoryStack memory is used to store method call frames, including local variables, parameters, and references to objects in heap memory. Each thread has its own stack, and memory is automatically released when a method completes.A stack frame can contain:Local variablesMethod parametersIntermediate computation dataReferences held in local variablesWhen the method finishes, its stack frame is removed automatically.Note: Local reference variables can refer to objects stored in the heap. The reference variable and the object it refers to are different things.Example
            Java

    public class Geeks {

    public static int calculate(int n)
    {
        int ans = n * 10;
        return ans;
    }

    public static void main(String[] args)
    {
        int n = 10;
        int result = calculate(n);

        System.out.println(result);
    }
}

Output100
Explanation:n and result are local primitive variables in main().The parameter n and local variable ans belong to the stack frame created for calculate().When calculate() finishes, its stack frame is removed.Note: Primitive local variables store their values directly as local-variable data. Local reference variables store references to objects rather than the objects themselves.3. MetaspaceMetaspace is a memory area used by the HotSpot JVM for storing class metadata. It replaced PermGen starting with Java 8. It stores information associated with loaded classes, such as their runtime metadata.Unlike the Java heap, Metaspace uses native memory.Note: Metaspace should not be confused with the Old Generation of the heap. Old Generation is associated with long-lived objects, whereas Metaspace is used for class metadata.4. Garbage CollectionJava uses garbage collection to automatically reclaim heap memory occupied by objects that are no longer reachable by the application. When an object can no longer be reached through any live reference, it becomes eligible for garbage collection. The exact time at which its memory is reclaimed is determined by the JVM and is not guaranteed to occur immediately.5. Memory Layout of an ObjectAt the JVM implementation level, an object's in-memory representation typically includes an object header, instance data, and possibly padding. The exact layout is JVM-implementation-dependent and can vary with JVM configuration.Object HeaderThe object header contains JVM-specific information used to manage the object. Depending on the JVM implementation and configuration, this may include information related to:The object's class/typeSynchronization and lockingGarbage collection and object stateInstance DataInstance data represents the values of the instance fields declared by the object's class and inherited from its superclasses.For example:class Student {
    int age;
    double marks;
}The values associated with age and marks form part of each Student object's instance data.PaddingPadding refers to extra unused bytes that the JVM may add to an object's memory layout to satisfy memory-alignment requirements. Proper alignment can help the JVM and underlying hardware access object data efficiently.Padding does not store actual application data.It may be added after the object's fields to align the total object size to a required memory boundary.The amount of padding can vary depending on the JVM implementation, object fields, and JVM configuration.Therefore, the actual memory occupied by an object can be slightly larger than the combined size of its fields and object header.How Java Objects Are Stored in MemoryThe following diagram illustrates how a Java object is stored in heap memory and accessed through a local reference variable in stack memory.
